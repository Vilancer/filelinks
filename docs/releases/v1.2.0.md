# filelinks v1.2.0

Release date: TBD (set on merge)
Milestone: v1.2 Claude Code, suggest, graph, git hook

## Highlights

- Added a **Claude Code provider** (`provider: 'claude'`) on `@anthropic-ai/claude-agent-sdk`, with two auth modes:
  - `claude.auth: 'device'` (default) reuses the Claude Code login and settings on the machine,
  - `claude.auth: 'token'` uses a `claude setup-token` token (or `ANTHROPIC_API_KEY`).
- Added **`filelinks suggest`**: a read-only agent pass that prints what each companion needs and never edits files.
- Added **`filelinks graph`**: terminal tree, Graphviz DOT, Mermaid, self-contained HTML, or JSON, with an optional `--staged` overlay.
- Shipped **`@vilancer/filelinks-git-hook`** (first release): `filelinks-git-hook install | uninstall | run` for plain git hooks and husky.
- Added **`check --run-agents --stage-fixes`**: stage the missing companions the agents wrote during the run, then re-check, so a fixed commit exits 0.

## User-facing changes

### `filelinks check`

- New flag: `--claude-token <token>` (Claude token override, `claude.auth: 'token'`).
- New flag: `--stage-fixes` (requires `--run-agents`). Only files the agents wrote during this run that are companions of a violated link are staged; your own unstaged edits are left alone.
- Without `--stage-fixes`, files the agents fixed are listed as `[agent] updated <path> (not staged)` with the `git add` to run.
- JSON mode adds `agentFixes: [{ path, staged }]` when agents ran.

### `filelinks suggest` (new)

- Same policy-eligible links as `check --run-agents`; Cursor runs in `plan` mode, Claude Code gets read-only tools.
- `--json` prints `{ "suggestions": [{ trigger, status, runId, suggestion }] }`.
- Flags: `--cursor-api-key`, `--claude-token`.

### `filelinks graph` (new)

- `--format terminal|dot|mermaid|html` (default `terminal`), `--output <file>`, `--staged`, and global `--json`.

### `filelinks add`

- Picks the provider (`cursor` / `claude`) and, for Claude, the auth mode. Cloud runtime stays Cursor-only.

### `@vilancer/filelinks-git-hook` (new package)

- `install [--husky] [--hook <name>] [--command <cmd>]`, `uninstall`, `run [--run-agents] [--stage-fixes]`.
- Writes an idempotent marked block into `.git/hooks/<hook>` (respects `core.hooksPath` and worktrees) or `.husky/<hook>`.
- `FILELINKS_SKIP=1` skips the check for one commit.

## Config additions

- `agent.provider: 'claude'`
- `agent.claude.auth: 'device' | 'token'`
- `agent.modelParams: [{ id: 'effort', value: 'low' | 'medium' | 'high' | 'xhigh' | 'max' }]` for Claude
- Default model per provider: `composer-2.5` (Cursor), `claude-opus-5-5` (Claude)

## Claude Code token resolution

1. `--claude-token`
2. `CLAUDE_CODE_OAUTH_TOKEN`, then `ANTHROPIC_API_KEY` (environment)
3. the same names in `.env.local`, then `.env`, under the effective `--cwd`

## Fixes

- The published `filelinks` bin was missing its `#!/usr/bin/env node` shebang, so it did not run directly on macOS/Linux.
- `.env` parsing now handles a quoted value followed by a `# comment`.

## Notes

- The Claude provider supports `runtime: 'local'` only.
- Claude Code tools are locked down: edits get Read/Glob/Grep/Edit/Write, `suggest` gets Read/Glob/Grep; no Bash, web, or MCP servers; nothing prompts.
- Existing `check` exit codes are unchanged unless `--stage-fixes` resolves the violations.

## Verification summary

- Core, CLI and git-hook tests passing; CLI E2E passing
- Type checks clean for lib and spec configs of all three packages
- Live smoke in a linked consumer: Claude Code `suggest`, `check --run-agents`, `--stage-fixes`, and the git hook
